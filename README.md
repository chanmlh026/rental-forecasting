# Rental Forecasting

An end-to-end data science and machine learning project to forecast average
monthly private rental prices 12 months ahead for each Local Authority in
England, initially for 1-, 2-, and 3-bedroom properties. The first planned data
source is the ONS Price Index of Private Rents (PIPR); other economic,
demographic, housing supply, and rental demand data may be added later.

## Project layout

| Path | Purpose |

| `data/processed/` | Cleaned, joined, and model-ready datasets such as Parquet files. |

| `src/processing/` | Validation, cleaning, and transformation. |

| `src/evaluation/` | Forecast metrics, diagnostics, and comparisons. |
| `src/pipelines/` | Orchestration of repeatable end-to-end workflows. |
| `dashboard/` | Future interactive application and presentation layer. |
| `reports/` | Generated analysis, forecasts, and project reports. |
| `tests/` | Automated unit and integration tests. |
| `configs/` | Non-secret project and environment configuration. |
| `infra/` | Future infrastructure-as-code and deployment resources. |
| `.github/workflows/` | Future GitHub Actions workflows. |

## Development setup

This project uses `pyproject.toml` for Python project metadata and
[uv](https://docs.astral.sh/uv/) for environment and dependency management.
The Python version is recorded in `.python-version`; pytest is included as a
development dependency for the smoke test.

With uv installed, create and synchronize the project environment with:

```powershell
uv sync
```

Run a Python script or the test suite through the project environment:

```powershell
uv run python path\to\script.py
uv run pytest
```

VS Code is configured to use `.venv` for this workspace and to activate it in
new integrated terminals. The data folders are excluded from version control
apart from their `.gitkeep` markers. Do not commit private, licensed, or
otherwise sensitive datasets.

## Data storage and future GCP deployment

`configs/storage.toml` records the intended storage settings. Keep data access
behind a small, shared storage/I/O layer and have pipelines read the storage
location from configuration rather than hard-coding paths. The local default
uses `./data`; the same logical data paths can later be mapped to a GCP Cloud
Storage bucket (for example, `gs://<bucket>/<prefix>`) by implementing a
compatible storage adapter. Do not put credentials or secrets in this file;
provide them through the runtime environment or a managed identity.

The layout leaves room for future Cloud Run Jobs for batch ingestion and
forecasting, Cloud Run Services for an application or API, and GitHub Actions
for automated checks and deployment. No GCP resources, CI workflows, model,
dashboard, or production container image are configured yet.

## ONS PIPR target ingestion

The initial ingestion supports the approved cohort of 294 English Local
Authorities, explicitly excluding City of London (`E09000001`) and Isles of
Scilly (`E06000053`). The pinned April 2025 ONS geography reference is
`configs/ons_lad_apr2025_v2.csv`. The output is one row per LA, month, and
bedroom category (1, 2, or 3), with rent in GBP per month.

Run the approved 21 October 2026 release with:

```powershell
uv run python -m ingestion.ons_pipr
```

Use `--release-id YYYY-MM-DD` and `--source-url URL` to select another
official edition. For offline parsing of a supplied workbook, pass
`--workbook path\to\workbook.xlsx`; the supplied bytes are still registered as
an immutable release snapshot. `--config` selects the existing storage
configuration, and `--geography-reference` selects the pinned geography file.
See [the ingestion guide](docs/006-ons-pipr-ingestion.md) for schemas, paths,
validation rules, and rerun behavior.

The release workbook and its SHA-256 metadata are kept under
`data/raw/ons_pipr/`. Validated source-derived Parquet is written under
`data/validated/ons_pipr/`, and the standardised long-format dataset,
manifest, and validation summary are written under
`data/processed/ons_pipr/`. Data files remain excluded from Git. The pipeline
does not create forecast labels, features, or train/test splits.

Run the automated tests with:

```powershell
uv run pytest
```

## Bank of England financing ingestion

Task 007 adds official Bank Rate effective-date events and IUMZID4 XML history.
Run from the repository root:

```powershell
uv run python -m ingestion.boe --snapshot-id 2026-11-21-task007 --end-date 2026-11-21
```

Use a new snapshot identifier and an explicit end date for each new retrieval.
Reuse the same arguments to verify and reprocess the saved source without a
download. `--dataset bank_rate` or `--dataset iumzid4` selects one component;
`--config` uses the existing storage TOML. The default end date is today's UTC
date. Keep the end date explicit for reproducible reruns.

Raw responses and provenance remain under `data/raw/bank_of_england/`.
Validated source tables and processed selected/history/event Parquet outputs
use the matching dataset/snapshot directories in the existing layers.
IUMZID4 selects the earliest recorded value, including provisional values,
with explicit uncertified-first-publication evidence status. It preserves all
returned history. Bank Rate retains event dates without monthly aggregation.
See [Task 007's implementation report](docs/007-boe-bank-rate-and-iumzid4-ingestion.md#implementation-report---21-november-2026)
for schemas, recovery, validation evidence and limitations.

## CPI/CPIH and UK HPI ingestion

Task 008 retains all four approved ONS inflation series by source vintage, and
all-property UK HPI prices/indices with a separate exact-code cohort view.

```powershell
uv run python -m ingestion.ons_inflation --snapshot-id 2026-11-21-task008
uv run python -m ingestion.uk_hpi --snapshot-id 2026-11-21-task008 --reference-month 2026-09
```

Use a new snapshot ID for each retrieval. Identical arguments reuse verified
raw responses without downloading; `--config` selects the existing storage
TOML. HPI also accepts `--geography-reference` for the pinned approved reference.
The inflation command retains current and latest advertised prior versions;
the HPI command retains the specified release and its England revision matrix.
Each retained vintage is separate; no first-release input policy is applied.

Outputs use the existing raw/validated/processed layers under `ons_inflation/`
and `uk_hpi/`. Source HTTP metadata is allowlisted. The HPI coverage tables
report every approved authority/month, preserving source geography and missing
cells without recoding or imputation. See [Task 008's report](docs/008-ons-inflation-and-uk-hpi-ingestion.md#implementation-report---21-november-2026)
for schemas, current measured coverage, source limitations and recovery.

## ASHE residence earnings ingestion

Task 009.2 preserves all 37 verified editions (2002–2026) of annual gross median
employee-job earnings, Table 8.7a `All` D, with paired 8.7b CVs, source markers,
styles, notes and original geography. It does not select modelling vintages or
harmonise historical authorities.

```powershell
uv run python -m ingestion.ons_ashe --snapshot-id YOUR-NEW-SNAPSHOT-ID
```

The pinned source inventory is `configs/ons_ashe_editions.json`. Optional
`--source-cache PATH` imports verified official response bundles, including the
Task 009.1 cache if explicitly supplied; it is not required for online retrieval.
Same-argument reruns reuse immutable snapshots without network access. Existing
storage TOML and geography-reference options apply. See the
[Task 009.2 report](docs/009.2-ons-ashe-earnings-ingestion.md#implementation-report---21-november-2026)
for outputs, recovery and source-note/publication limitations.

## Nomis model-based unemployment ingestion

Task 009.4 retains the approved NM_127_1 ITEM 2 published unemployment rate
(20100) and confidence margin (20701) for 87 rolling annual periods, end-month
2004-12 through 2026-06, with original TYPE424 geography and all source areas.

```powershell
uv run python -m ingestion.nomis_umb --snapshot-id YOUR-NEW-SNAPSHOT-ID
```

Optional `--source-cache data/raw/umb-009-3-investigation` imports verified
retained official responses without repeating successful data downloads; a missing
terms response is retrieved once. `--config`, `--contract` and
`--geography-reference` use the existing project configuration. Same-argument
reruns reuse immutable snapshots. Interrupted runs retain completed requests;
rerun with the same snapshot ID to resume. Changed contracts, source bytes or
completed outputs cannot overwrite that snapshot.

Raw, validated and processed outputs use `nomis_umb/snapshot={id}/` in the
existing storage layers. Source missingness, confidence gaps, original geography,
notes, release/revision metadata and original value strings remain intact. No
monthly conversion, imputation, harmonisation or model-input vintage is selected.
See the [Task 009.4 report](docs/009.4-nomis-umb-unemployment-ingestion.md#implementation-completion-report---22-november-2026)
and [reproducible audit](reports/data_audits/009.4/README.md). Future historical or
geography extensions require separate approval of the pinned contract.

## ONS population, published area/density and migration ingestion

Task 010 implements the approved offline scope from nine verified ONS workbooks.
The pinned `configs/ons_population_sources.json` retains each source edition,
geography sheet and checksum separately. Population/density cover 2011-2025;
detailed migration components cover years ending mid-2012 through mid-2025.

```powershell
uv run python -m ingestion.ons_population --snapshot-id 2026-11-22-task010
uv run python reports/data_audits/010/validate_ingestion.py
```

These commands require the retained ignored source bundles. The production CLI
is offline-only: missing sources stop without downloading. Further automated ONS
acquisition requires owner approval of a suitable non-personal project contact;
five advertised superseded files remain unacquired. Do not use a placeholder,
personal contact or substitute data. Existing raw responses retain their original
request/retrieval provenance.

Outputs use existing raw/validated/processed `ons_population/snapshot={id}/`
layers. The six tables retain original values/precision, markers, notes/styles,
source geography, release evidence and measured coverage. Area remains a source
cell without an invented reference year. No growth, density or migration ratio
is calculated. `--config`, `--inventory` and `--geography-reference` reuse the
existing project settings; completed snapshots cannot be overwritten. Rerun the
same arguments to verify/recover from saved requests without network access.

See [Task 010](docs/010-ons-population-area-and-migration-ingestion.md) and the
[offline audit/evidence](reports/data_audits/010/README.md) for validated coverage,
remaining geography/publication limitations and the blocked acquisition follow-up.
