# Rental Forecasting

An end-to-end data science and machine learning project to forecast average
monthly private rental prices 12 months ahead for each Local Authority in
England, initially for 1-, 2-, and 3-bedroom properties. The first planned data
source is the ONS Price Index of Private Rents (PIPR); other economic,
demographic, housing supply, and rental demand data may be added later.

## Project layout

| Path | Purpose |
| --- | --- |
| `data/raw/` | Unmodified source data, including downloaded ONS files. |
| `data/external/` | Data from external sources that is not owned or generated by this project. |
| `data/processed/` | Cleaned, joined, and model-ready datasets such as Parquet files. |
| `notebooks/` | Exploratory analysis and experiments; production logic belongs in `src/`. |
| `src/ingestion/` | Source data acquisition and loading. |
| `src/processing/` | Validation, cleaning, and transformation. |
| `src/features/` | Feature construction for forecasting. |
| `src/models/` | Model definitions and training workflows. |
| `src/evaluation/` | Forecast metrics, diagnostics, and comparisons. |
| `src/pipelines/` | Orchestration of repeatable end-to-end workflows. |
| `dashboard/` | Future interactive application and presentation layer. |
| `reports/` | Generated analysis, forecasts, and project reports. |
| `tests/` | Automated unit and integration tests. |
| `configs/` | Non-secret project and environment configuration. |
| `infra/` | Future infrastructure-as-code and deployment resources. |
| `.github/workflows/` | Future GitHub Actions workflows. |

## Development setup

This project uses `pyproject.toml` for Python project metadata and
[uv](https://docs.astral.sh/uv/) for environment and dependency management.
The Python version is recorded in `.python-version`; pytest is included as a
development dependency for the smoke test.

With uv installed, create and synchronize the project environment with:

```powershell
uv sync
```

Run a Python script or the test suite through the project environment:

```powershell
uv run python path\to\script.py
uv run pytest
```

VS Code is configured to use `.venv` for this workspace and to activate it in
new integrated terminals. The data folders are excluded from version control
apart from their `.gitkeep` markers. Do not commit private, licensed, or
otherwise sensitive datasets.

## Data storage and future GCP deployment

`configs/storage.toml` records the intended storage settings. Keep data access
behind a small, shared storage/I/O layer and have pipelines read the storage
location from configuration rather than hard-coding paths. The local default
uses `./data`; the same logical data paths can later be mapped to a GCP Cloud
Storage bucket (for example, `gs://<bucket>/<prefix>`) by implementing a
compatible storage adapter. Do not put credentials or secrets in this file;
provide them through the runtime environment or a managed identity.

The layout leaves room for future Cloud Run Jobs for batch ingestion and
forecasting, Cloud Run Services for an application or API, and GitHub Actions
for automated checks and deployment. No GCP resources, CI workflows, model,
dashboard, or production container image are configured yet.
